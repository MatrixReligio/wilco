# 批准与通知

## 批准

Wilco Host 启动的每个会话都运行在 [wilco-guard](../../Bridge/README.zh-CN.md#wilco-guard) 之下。在 Pi 执行有风险的命令（`rm -r`、`sudo`、`git push --force` 等）或在文件夹之外写入之前，它会停下来询问你。问题会出现在你 iPhone 或 iPad 上的会话里，Pi 会一直等待（没有时间限制），直到你批准或拒绝。

wilco-guard 是防止失误的安全网，而不是沙盒：Pi 以你的身份运行，专门为绕过规则而写的命令（例如借助脚本文件）是可以绕过的。需要时请打开“所有命令”，Pi 执行每条命令前都会询问。

询问哪些操作，在 App 的“设置 → 你的 Mac → 需要批准”中选择。规则保存在 Mac 上，并立即作用于正在运行的会话；参见 [wilco-guard 与 Wilco Host](../../Bridge/README.zh-CN.md)。

## 通知

在“设置 → 通知”中打开。可以接收：

- **询问与批准**：Pi 在等你。
- **运行完成**：Pi 完成了你交代的事，附带回答的开头。
- **运行出错**：一次运行因错误而停止。

通知是端到端加密的。你的 Mac 为每条通知加密，只有你的设备能打开；Wilco 的推送服务只负责转发，无法读取内容。参见 [Protocol/push.zh-CN.md](../../Protocol/push.zh-CN.md)。

### 在锁屏上批准

关于命令的询问，如果完整的命令能在通知里显示，通知上会直接出现 **批准** 和 **拒绝**。两者都需要面容 ID、触控 ID 或密码。过长的命令、跨多行的命令，或含有看不见的字符的命令，会改为在 App 中打开这个询问，确保你批准的正是你看到的内容。

## 实时活动

从 App 发送提示后，这次运行会出现在锁屏和灵动岛上：Pi 是在工作还是在等你、用了多少步、已经多长时间。它只显示文件夹和 Mac 的名称，从不显示你的代码或命令。Pi 等待“是或否”的回答时，它提供 **拒绝**，以及一个打开询问的按钮，你可以在 App 中阅读后再批准。可以在“设置 → 通知”中关闭实时活动。

## 小组件

把 **Pi 会话** 小组件添加到主屏幕，就能看到哪些需要你处理、Pi 正在做什么。点按某个会话即可打开。iPhone 锁定时会隐藏会话名称。

## Siri 与快捷指令

- “用 Wilco 问 Pi”：在你选择的文件夹中，用你的请求开始一个新会话。
- “Wilco 里 Pi 在做什么”：告诉你哪些需要你处理、哪些正在运行。

两者都需要 iPhone 解锁后才能使用。
