# 安全模型

## 哪些东西留在你的 Mac 上

代码仓库、模型服务凭据和 Pi 会话历史。Wilco 没有账号体系，也没有云端数据库。

## 配对

1. Mac Host 显示一个二维码，内含 Host 公钥、Host ID、中继频道，以及一个 10 分钟后失效的一次性配对密钥。
2. 手机扫码后，基于该密钥执行 **Noise XXpsk3** 握手（X25519、ChaCha20-Poly1305、SHA-256）。
3. Host 显示设备名称和 6 位确认码，由你在 Mac 上批准。
4. 双方保存对方的静态公钥。之后每次连接都使用 **Noise IK** 握手，双方每次都要证明自己的身份。

密钥保存在 iOS 和 macOS 的钥匙串中，永远不会离开生成它的设备。在 Mac 上撤销某台设备后，它会立即断开，其中继令牌也随即失效。

## 中继能看到什么

中继只能看到频道 ID、连接时间和加密帧的大小。它无法读取提示词、代码、工具输出或文件名，也不保存任何内容。

## 推送通知

通知内容在离开 Mac 之前就已针对你的设备加密，到达手机后由通知服务扩展解密。Apple 和中继只能看到密文。

**例外：实时活动（Live Activity）。** iOS 无法在设备上解密实时活动的远程更新，因此远程更新只携带最少的非敏感字段：状态、步数、耗时和"需要你处理"标记，绝不包含文件名或文本。App 运行时，会在本地用更丰富的信息更新实时活动。

## 工作区边界

授权工作区决定三件事：手机可以在哪些目录启动或恢复会话、可以浏览哪些文件、可以列出哪些会话。路径会被规范化，指向工作区之外的符号链接会被拒绝。

**Pi 自带的工具**（read、write、edit、bash）沿用 Pi 原有的信任模型，与你直接在 Mac 上使用 Pi 时一样。Wilco 不对 Pi 做沙盒隔离。如需更多防护，可以启用 `wilco-guard` 审批策略；默认策略会在执行危险的 shell 命令和写入工作区外的文件前请求批准。这些策略用来拦住失误，并不是沙盒：Pi 以你的身份运行，专门为绕过它们而写的命令是可以绕过的。

## 手机可以发送的命令

Host 会对照策略表检查每条命令。可能指定任意路径的命令（例如切换到某个会话文件、把 HTML 导出到指定路径）只能通过 Host 提供的安全操作间接完成。从手机直接执行 shell 命令默认关闭，需要按设备单独开启。
