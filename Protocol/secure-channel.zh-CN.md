# 安全通道（协议版本 1）

Wilco 客户端（设备）与 Wilco Host 之间的所有数据都经过这条通道，无论走局域网、直连地址还是 Wilco 中继。中继只能看到密文。

## 连接前导

设备在新连接上发送的第一条消息（早于任何握手消息）是 4 个字节：`"WLC"` ‖ 模式，模式 `0x01` 表示配对握手，`0x02` 表示重连。它与 Noise 消息一样分帧。遇到其他前导、在没有有效邀请时收到配对前导，或握手及设备的 `hello` 未在 15 秒内完成时，Host 直接关闭连接，不作任何回复。（配对设备发出 `hello` 后，会一直等待所有者的决定，直到邀请结束。如果所有者拒绝，或邀请先结束，Host 会在关闭连接前以 `error`（`pairing_rejected` 或 `pairing_expired`）回复该 `hello`；重连的未知设备或已撤销设备不会得到任何回复。设备若到邀请结束时仍未收到回复，稍后即放弃等待。）

## 握手

设备始终是 Noise **发起方**，Host 是**响应方**。双方使用 Curve25519、ChaCha20-Poly1305 和 SHA-256，严格按 [Noise 协议框架](https://noiseprotocol.org/noise.html)第 34 版实现。

| 用途 | 模式 | Prologue |
|---|---|---|
| 首次配对 | `Noise_XXpsk3_25519_ChaChaPoly_SHA256`，psk 为邀请中的 32 字节一次性密钥 | `"wilco/pair/1"` ‖ `0x00` ‖ UTF-8 编码的 Host ID |
| 之后的每次连接 | `Noise_IK_25519_ChaChaPoly_SHA256`，设备已知 Host 的静态公钥 | `"wilco/1"` ‖ `0x00` ‖ UTF-8 编码的 Host ID |

实现必须逐字节复现 [`test-vectors/noise/`](test-vectors/noise/README.md) 中的测试向量。

握手载荷与确认：

- **所有握手消息的载荷都为空**，两个方向都是。
- 握手完成后由设备先发言：它的第一条传输消息是 `hello` 控制消息。
- **Host 只有在这第一条传输消息解密成功后，才认为设备已连接。** IK 的第 1 条消息可以被重放：截获过它的人能让 Host 再完成一次握手，但无法用新密钥构造传输消息。在第一条消息解密成功之前，Host 不记录任何东西（不更新"最近在线"、不标记在线、不替换已有连接），也不发送任何东西。
- 随后 Host 核验设备的静态公钥：重连时查设备注册表（未知或已吊销的公钥直接断开，不作任何回复），配对时由主人批准。之后 Host 才发送它的第一条传输消息 `hello.ok`。
- XX 中，设备会核对第 2 条消息揭示的 Host 静态公钥是否与邀请中的一致；不一致就中止。
- Host 只在邀请有效期内接受配对握手：同一时间最多一个邀请；过了 `x` 或已有设备凭它获批后即拒绝。此判断不信任设备的时钟。
- 握手中出现任何错误都会结束本次尝试，重试需要从头开始。

## 配对邀请

Host 显示一个二维码，内容是链接：

```text
wilco://pair#<base64url(JSON)，无填充>
```

全部内容都放在 URL 片段（fragment）中，客户端不会把它发给任何服务器。JSON 对象的键如下：

| 键 | 类型 | 含义 |
|---|---|---|
| `v` | 整数 | 邀请格式版本，`1` |
| `h` | 字符串 | Host ID |
| `n` | 字符串 | Host 显示名称 |
| `k` | base64url | Host 静态 X25519 公钥（32 字节） |
| `r` | 字符串，可选 | 中继频道 ID（见[中继](relay.zh-CN.md)） |
| `u` | 字符串，可选 | 中继地址，Host 使用非默认中继时提供 |
| `t` | 字符串，可选 | 中继配对令牌，使设备能通过中继配对 |
| `l` | 字符串数组 | 局域网提示，形如 `host:port` |
| `s` | base64url | 一次性配对密钥（32 字节） |
| `x` | 整数 | 过期时间（Unix 秒）；邀请有效期 10 分钟 |

客户端遇到以下情况一律拒绝：scheme 或 host 不对、`v` 未知、字段缺失或类型错误、密钥长度不对、`当前时间 ≥ x`。

### 确认码

XX 握手完成后，两端屏幕都显示一个 6 位确认码。两边的码一致，说明双方完成的是同一次握手；Host 的主人在此之后才批准该设备。

```text
code = UInt64(大端序，取 HMAC-SHA256(key: handshake_hash, "wilco pairing code") 的前 8 字节) mod 1 000 000
```

不足六位时在前面补零。

## 传输消息

握手完成后，双方各得到一个发送密码和一个接收密码（Noise `Split()`）。nonce 是隐式计数器，所以重放、乱序或丢失的消息都会解密失败。**任何解密或格式错误都会结束会话。**

一条应用消息（一个 Wilco 信封）可能超过单条 Noise 消息的上限（65535 字节），因此会拆成分片。每个分片的明文是：

```text
标志（1 字节：0x00 = 后面还有分片，0x01 = 最后一片） ‖ 最多 65518 字节的消息内容
```

- 每个分片加密为一条 Noise 传输消息，关联数据为空。
- Noise 消息必须按加密的先后顺序发送。
- 空消息就是一个单独的最后分片。
- 非最后分片不能为空，标志取其他值都视为错误。
- 接收方限制拼装后消息的最大长度（默认 64 MiB），并在缓冲超过上限之前就让会话失败。

## 分帧

- **字节流（TCP）：** 每条 Noise 消息前加 2 字节大端序长度。长度为 0 视为错误。
- **消息型传输（经中继的 WebSocket）：** 每条 Noise 消息对应一条二进制 WebSocket 消息。
